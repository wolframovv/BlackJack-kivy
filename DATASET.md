# Датасет решений для обучения ботов

Игра сама пишет два CSV-файла в папку данных приложения. Записываются **только завершённые
раунды** (если выйти в меню посреди раунда, его строки не сохраняются).

| Файл | Одна строка | Зачем |
|---|---|---|
| `blackjack_decisions_v1.csv` | одно решение игрока | модель действий (hit/stand/...) |
| `blackjack_rounds_v1.csv` | один раунд | модель размера ставки |

`v1` в имени — версия схемы. Если колонки изменятся, начнётся новый файл (`v2`).

## Где лежат файлы
Файлы появляются **после первого завершённого раунда** (с итоговой панелью «Новая игра / Меню»).
Счётчик записанного виден в профиле: «Данные для обучения (решений / раундов)».

- **ПК** (`python main.py`): папка `data/` рядом с `main.py`. Путь также печатается в консоль
  строкой «Датасет решений: ...». Другую папку можно задать переменной
  `BLACKJACK_DATA_DIR=/путь python main.py`.
- **Android (debug-сборка):** файлы в закрытой папке приложения, обычным файловым менеджером их
  не видно. Забрать на компьютер:
  ```
  adb exec-out run-as org.blackjack.blackjack cat files/blackjack_decisions_v1.csv > blackjack_decisions_v1.csv
  adb exec-out run-as org.blackjack.blackjack cat files/blackjack_rounds_v1.csv > blackjack_rounds_v1.csv
  ```
  Список файлов в папке: `adb shell run-as org.blackjack.blackjack ls files`

Проверка собранного: `python tools/dataset_stats.py blackjack_decisions_v1.csv`

## Колонки `blackjack_decisions_v1.csv`

**Идентификаторы** (в признаки не брать): `round_id`, `decision_idx` (номер решения в раунде),
`timestamp` (UTC), `player`.

**Признаки состояния** (значения в момент решения, до действия):

| Колонка | Смысл |
|---|---|
| `balance` | баланс игрока (ставка уже списана) |
| `bet` | ставка на текущую руку |
| `bet_pct` | `bet` / деньги до раунда |
| `player_total` | сумма очков текущей руки |
| `player_soft` | 1 — «мягкая» рука (туз считается за 11) |
| `n_cards` | карт в руке |
| `is_pair` / `pair_value` | 1, если две карты одного ранга / очки карты пары (иначе 0) |
| `hand_index` / `n_hands` | номер руки (после сплита 0 или 1) / сколько рук |
| `split_used` | 1 — сплит в этом раунде уже был |
| `dealer_up` | очки открытой карты дилера (2..11, туз = 11) |
| `dealer_up_ace` | 1 — у дилера открыт туз |

**Допустимые действия:** `can_hit`, `can_stand`, `can_double`, `can_split`, `can_surrender`,
`can_insure`.

**Метка:** `action` — одно из `hit`, `stand`, `double`, `split`, `surrender`, `insurance`,
`no_insurance`.

**Исход раунда** (повторяется во всех строках раунда): `round_result`
(`win`/`loss`/`tie`/`blackjack`/`surrender`), `round_net` (чистый результат в фишках, страховка
включена), `round_net_per_bet` (то же в долях начальной ставки: +1, −1, +1.5, −0.5 ...).

**Читаемо:** `player_cards` (например `AS 7H`), `dealer_up_card`.

## Важные правила для обучения

1. **Исход раунда (`round_*`) нельзя брать в признаки.** Это утечка из будущего: модель
   «узнает» результат, которого на момент решения ещё нет. Колонки нужны для анализа и
   взвешивания примеров.
2. **Маска допустимых действий.** Бот обязан выбирать только из разрешённых действий:
   `insurance` и `no_insurance` разрешены при `can_insure = 1`, остальные — по своим флагам
   (`hit` ↔ `can_hit`, и так далее). Иначе модель предложит сплит без пары. Для модели с
   `predict_proba`: обнулить вероятности запрещённых действий и нормировать остаток.
3. **Страховка** — отдельный тип решения: строки с `can_insure = 1` содержат только
   `insurance`/`no_insurance`.
4. **Автоматические ходы не пишутся:** набор 21 (автоматическая остановка), перебор и ход
   дилера — это не решения игрока.
5. **Дисбаланс классов.** `hit` и `stand` будут составлять большую часть данных, а `split`,
   `surrender` и страховка — единицы процентов. Для них нужно намного больше раундов.
6. **Бот будет копировать вас**, в том числе ваши ошибки. Это ожидаемо при обучении на
   демонстрациях человека.

## Колонки `blackjack_rounds_v1.csv`
`round_id`, `timestamp`, `player`, `bankroll_start` (деньги до ставки), `bet`, `bet_pct`,
`prev_net_per_bet` (результат предыдущего раунда в этой сессии, пусто для первого),
`n_decisions`, `insured`, `surrendered`, `round_result`, `round_net`, `round_net_per_bet`.
Для модели ставки признаки: `bankroll_start`, `prev_net_per_bet`; метка: `bet_pct`.

## Правила игры (для справки)
- **Страховка:** предлагается, только если у дилера открыт туз. Стоит половину ставки (округление
  вниз), нужен достаточный баланс. Если у дилера блэкджек, выплата 2:1 (ставку страховки вы
  получаете обратно и ещё удвоенную), поэтому в этом раунде вы остаётесь при своих. Если блэкджека
  нет, страховка проигрывается и игра продолжается. При вашем блэкджеке и тузе у дилера результат
  равен «1 к 1» в любом случае.
- **Сдаться:** только первым действием на двух картах, до карт, сплита и удвоения (блэкджек дилера
  проверяется до вашего хода, так что после его блэкджека сдаться нельзя). Возвращается половина
  ставки (округление вниз; при ставке 1 сдаться нельзя). В статистике — поражение.
